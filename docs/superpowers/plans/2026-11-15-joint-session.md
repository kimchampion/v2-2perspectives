# Joint-session implementation plan

**Goal:** Enable controlled two-device testing on the existing free-tier-compatible Node/Socket.IO server while preserving the one-device flow and local drafts.

**Authorized scope:** The user's acceptance of the recommendation authorizes transient server transmission of participant names/avatars and explicitly submitted responses for a joint session. Drafts remain in React memory. No disk/browser persistence, analytics, accounts, catalog data transmission, or deployment is included.

**Experience:** A creator accepts rules, builds their persona, and chooses Enter joint session. A partner can enter the shared code from welcome, accept the same rules, and build their own persona. The creator chooses the scenario after both join. Each device shows only its assigned perspective and draft. Explicit submission can contain empty text and/or drawing. A waiting screen replaces a submitted draft until both submit; then both devices reveal the same responses. Reflection choices, choosing a new scenario, and ending are shared. Connection banners, retry, and a server-waking message support free-tier startup and network interruptions. Rejoin credentials remain in memory, so refreshing does not promise recovery.

**Wire contract:** POST /api/sessions returns `{code, hostToken}`. Join payload is `{code, participant:{name,avatar}, hostToken?, resumeToken?}`; a 64-hex resumeToken can be supplied on first join to make lost-ack retries idempotent. Host token reserves participant 0, guest uses participant 1. Join acknowledgement is `{ok:true, session, resumeToken}`; all other command acknowledgements are `{ok:true, session}` or `{ok:false,error:{code,message}}`. Per-device `session-state` snapshots contain `{code, participantIndex, round, revision, phase, scenarioId, reflectionPath, participants:[null|{name,avatar,connected,submitted}, ...]}`. Only phase `revealed` contains `responses:[{mode,text,drawing,color,submitted:true}, ...]`. Ended snapshots clear participant/response data. Commands: `select-scenario:{scenarioId,round}`, `submit-perspective:{response:{mode,text,drawing,color},expression,round}`, `choose-repair-step:{repairChoice,round}`, `restart-scenario:{round}`, `end-session:{round}`. Validate payloads and stable ownership, reject stale rounds, and lock each submitted response. Host alone selects a scenario; either participant may share reflection, restart after reveal, or end.

**Files:** Server factory/store and loopback tests own the protocol. Existing session client owns bounded HTTP/ack transport; a new React hook owns in-memory connection credentials and reconnect. Existing reducer accepts validated snapshots while preserving the current user's unsubmitted draft. Existing Setup, Conversation, Reflection and Welcome are reused with small joint controls/status additions. No components directory is created. Seed copy stays in src/data.js; production base remains `/`.
